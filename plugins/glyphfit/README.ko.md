> glyphfit은 텍스트 크기에 맞춰 이미지를 줄이지만, 플랫폼의 native-resolution cap이 이미 큰 이미지를 축소하며 — 텍스트 기반 축소는 출력이 그 cap 아래에 머물 때만 토큰을 절감합니다. 실제로 그 구간은 좁습니다: 작거나 크롭한 이미지, 저해상도 환경, 또는 반복해서 읽는 이미지. 대부분의 스크린샷은 원본을 그대로 읽어도 비용이 같습니다. 그래도 쓰려면 `claude plugin enable glyphfit` 또는 `/plugin config glyphfit`.

## 왜 glyphfit인가?

Claude는 과금 전에 모든 이미지를 모델의 **native resolution**까지 먼저 축소합니다 — 구형 모델은 긴 변 ~1568px, **Opus 4.7+는 2576px**까지(이미지당 상한도 ~1,600에서 ~4,784 토큰으로 상향). 그다음 대략 이렇게 과금합니다:

```
tokens ≈ (축소 후 width × height) / 750
```

그래서 큰 스크린샷도 전체 픽셀만큼 들지 않습니다 — Claude가 상한 아래로 먼저 줄이니까요. **하지만 이 내장 축소는 내용을 모릅니다**: 글자가 얼마나 작은지와 무관하게 원시 픽셀로만 줄입니다.

glyphfit은 대신 텍스트를 고려해 줄입니다 — 가장 작은 텍스트 줄을 재서, 그 줄이 가독 임계선에 닿도록 크기를 맞춥니다. 단, 여기에 분명한 한계가 있습니다: glyphfit은 **출력이 플랫폼의 native-resolution 상한 아래에 머물 때만 토큰을 절감합니다.** 그래서 효과가 깔끔하게 갈립니다:

- **효과가 있는 곳** — 애초에 상한에 안 걸리는 이미지: 작거나 크롭한 이미지, 확대 캡처, 해상도 대비 텍스트가 큰 이미지. 여기선 줄인 픽셀이 그대로 토큰 절감으로 이어집니다(1024×768 텍스트 스크린샷을 floor 18로 → ~635×476, 약 −60%), 가독성 손실 없이. 반복해서 읽는 이미지도(축소가 캐시됨).
- **효과가 없는 곳** — 이미 상한을 한참 넘는 빽빽한 전체 화면 캡처(4K/retina). Claude가 어차피 native resolution으로 줄이고, glyphfit의 텍스트 기반 출력도 그 같은 한도 위에 떨어지므로 — **절감할 게 거의 없습니다.** 이 경우 glyphfit은 그저 더 작은 사본을 돌려줄 뿐, 다운스트림에서 같은 크기로 다시 줄여집니다.

요약하면: glyphfit은 **작거나, 크롭했거나, 확대해서 픽셀 수 대비 텍스트가 큰 이미지**에서 효과가 있고 — 플랫폼이 어차피 줄일 크고 빽빽한 전체 화면 캡처에서는 그렇지 않습니다.

## 설치

glyphfit은 이미지 파이프라인을 [uv](https://docs.astral.sh/uv/)로 실행하므로, uv가 설치되어 `PATH`에 있어야 합니다:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # macOS / Linux — Windows는 uv 문서 참조
```

그다음 플러그인을 추가·설치합니다:

```bash
/plugin marketplace add byExist/plugins
/plugin install glyphfit@plugins
```

첫 세션에서 uv가 의존성(Pillow, RapidOCR)을 로컬 virtualenv에 설치합니다. 검출 모델은 RapidOCR 패키지에 번들돼 있어(~4.5 MB) 런타임 다운로드가 없으며, 첫 실행 비용은 '다운로드'가 아니라 엔진 초기화(모델 로드)입니다.

## 사용법

설치하면 끝입니다. 평소처럼 Claude에게 이미지를 읽게 하면, Claude가 목적에 따라 알아서 고릅니다 — 텍스트를 읽는 작업이면 이미지를 줄여서 보고, 디자인·픽셀 정확도가 필요한 작업이면 원본을 봅니다.

이 판단은 별도 스킬이 아니라 hook이 만듭니다. 세션에서 이미지를 처음 읽을 때, glyphfit이 "텍스트면 줄이고, 디자인이면 원본"이라는 1회성 안내를 Claude에게 주입합니다. 그래서 매번 지시하지 않아도 대개 올바른 선택이 일어납니다.

직접 개입하고 싶다면:

- **줄여서 보게** — "줄여서 읽어줘"처럼 말하면 Claude가 축소본을 읽습니다.
- **원본을 보게** — "원본 그대로 봐줘"라고 하거나, 픽셀 정확도가 중요하다고 알려주세요.
- **아예 끄려면** — `/plugin config glyphfit`에서 `enabled`를 끄면 모든 `Read`가 손대지 않고 통과합니다.

## 동작 원리

`shrink:`가 붙은 `Read`를 가로채면, glyphfit은 단순 비율 축소가 아니라 **가장 작은 글자가 읽히는 선까지만** 줄입니다:

1. **텍스트 줄 검출** — RapidOCR(DBNet)로 텍스트 줄의 위치를 찾습니다. 글자를 *인식*하진 않고(인식 단계 off → 비용 ~70% 절감), 각 박스의 **짧은 변**(가로·세로 중 작은 쪽, px)만 잽니다 — 가로쓰기든 세로쓰기(일본어 등)든 글자 크기를 잡아냅니다.
2. **기준 크기 선택** — 하위 `outlier_percentile`%(기본 5%)는 얼룩·노이즈로 버리고, 그다음으로 작은 박스의 짧은 변을 기준으로 삼습니다.
3. **스케일 계산** — `scale = floor / 기준크기` (상한 1.0). 가장 작은 비-노이즈 글자가 `floor_char_height_px`(기본 18px)에 닿도록 하는 비율이며, 이미 그보다 크면 줄이지 않습니다.
4. **1회 리사이즈** — Lanczos로 한 번 줄여 무손실 WebP로 캐시합니다. 같은 이미지·설정의 다음 읽기는 캐시 적중(~100 ms).

검출되는 텍스트가 없으면(사진·아이콘·다이어그램) 원본을 그대로 돌려줍니다. 인식을 끄기 때문에 글자 종류(한글/한자 등)는 구분하지 못해서, 문자 체계에 맞는 `floor_char_height_px`는 설정에서 지정합니다.

## 설정

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `floor_char_height_px` | `18` | 출력 이미지에서 가장 작은 비노이즈 글자의 최소 크기(px, 박스의 짧은 변). 권장: **12**(라틴 전용), **18**(한글/가나, 기본값), **24**(간체 CJK), **32**(번체 CJK). |
| `outlier_percentile` | `5` | 검출된 글자 크기 중 하위 N%는 노이즈로 폐기. |
| `min_pixels_for_action` | `200000` | 이보다 작은 이미지는 `shrink:` 가 붙어도 그대로 통과. |
| `enabled` | `true` | 전체 파이프라인 토글. off면 `shrink:`는 제거되지만 원본이 반환됩니다. |

`/plugin config glyphfit`으로 변경.

## 트레이드오프

- **컨텐츠의 문자 체계에 맞춰 `floor_char_height_px`를 설정하세요.** 한국어/일본어는 ~18, 한자는 ~24가 적절. 기본값은 한국어에 안전한 값입니다.
- **첫 실행 비용.** 첫 세션에서 `uv sync`가 의존성(Pillow, ONNX Runtime, RapidOCR — 수십 MB, 캐시가 없으면 더 느림)을 설치합니다. 검출 모델은 RapidOCR에 번들돼 있어(~4.5 MB) 별도 다운로드가 없고, 새 프로세스마다 그것을 로드(엔진 초기화)할 뿐입니다. 이후 캐시 적중은 ~100 ms입니다.
- **`shrink:`가 no-op일 수 있음.** 검출되는 텍스트가 없거나(사진/아이콘/다이어그램), 이미 작거나(~200k px 미만), 텍스트가 이미 floor 이상이면 원본이 그대로 반환됩니다.
- **캐시 적중은 거의 무료.** 같은 이미지 + 같은 설정이면 ~100 ms.
