## 왜 glyphfit인가?

Claude는 과금 전에 모든 이미지를 먼저 축소합니다 — 긴 변 ~1568px, 총 ~1.15 메가픽셀 이하로 — 그다음 대략 이렇게 과금합니다:

```
tokens ≈ (축소 후 width × height) / 750   # 이미지당 최대 ~1,600 토큰
```

그래서 3680×2382 스크린샷은 ~11,700 토큰이 아니라, Claude가 상한 아래로 먼저 줄여 **~1,530 토큰** 정도입니다. 하지만 이 내장 축소는 **내용을 모릅니다** — 글자가 얼마나 작은지와 무관하게 원시 픽셀로만 줄입니다. 이미 상한 이하인 이미지나 여러 번 읽는 이미지는, 텍스트를 읽는 데 필요 없는 픽셀까지 그대로 비용을 냅니다.

glyphfit은 텍스트를 고려해 축소합니다. 가장 작은 텍스트 줄의 위치를 측정해, 그 줄이 가독 임계선에 닿도록 크기를 줄입니다. 출력이 **Claude의 ~1568px / 1.15MP 상한 아래**에 머무를 때, 토큰 비용은 줄인 픽셀에 비례해 감소합니다 — 예: 1024×768 텍스트 스크린샷을 floor 18로 줄이면 약 635×476이 되어, 이 경우 **약 −60% 토큰**, 가독성 손실 없이.

**효과가 큰 곳:** 이미 상한 이하인 중간 크기 스크린샷(픽셀 절감이 그대로 토큰 절감으로), 반복해서 읽는 이미지(축소 결과가 캐시됨). **효과가 없는 곳:** 줄인 뒤에도 여전히 상한보다 큰 초대형 스크린샷 — Claude가 어차피 ~1.15MP로 줄이므로, glyphfit 출력이 그 한도 아래로 내려가기 전까지는 절감이 없습니다.

## 설치

glyphfit은 이미지 파이프라인을 [uv](https://docs.astral.sh/uv/)로 실행하므로, uv가 설치되어 `PATH`에 있어야 합니다:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh   # macOS / Linux — Windows는 uv 문서 참조
```

그다음 플러그인을 추가·설치합니다:

```bash
/plugin marketplace add byExist/plugins
/plugin install glyphfit@plugins
```

첫 세션에서 uv가 의존성(Pillow, RapidOCR)을 로컬 virtualenv에 설치하고, text-detection 모델(~50 MB)은 첫 `shrink:` 읽기에서 1회 다운로드합니다.

## 사용법

설치하면 끝입니다. 평소처럼 Claude에게 이미지를 읽게 하면, Claude가 목적에 따라 알아서 고릅니다 — 텍스트를 읽는 작업이면 이미지를 줄여서 보고, 디자인·픽셀 정확도가 필요한 작업이면 원본을 봅니다.

이 판단은 별도 스킬이 아니라 hook이 만듭니다. 세션에서 이미지를 처음 읽을 때, glyphfit이 "텍스트면 줄이고, 디자인이면 원본"이라는 1회성 안내를 Claude에게 주입합니다. 그래서 매번 지시하지 않아도 대개 올바른 선택이 일어납니다.

직접 개입하고 싶다면:

- **줄여서 보게** — "줄여서 읽어줘"처럼 말하면 Claude가 축소본을 읽습니다.
- **원본을 보게** — "원본 그대로 봐줘"라고 하거나, 픽셀 정확도가 중요하다고 알려주세요.
- **아예 끄려면** — `/plugin config glyphfit`에서 `enabled`를 끄면 모든 `Read`가 손대지 않고 통과합니다.

## 동작 원리

`shrink:`가 붙은 `Read`를 가로채면, glyphfit은 단순 비율 축소가 아니라 **가장 작은 글자가 읽히는 선까지만** 줄입니다:

1. **텍스트 줄 검출** — RapidOCR(DBNet)로 텍스트 줄의 위치를 찾습니다. 글자를 *인식*하진 않고(인식 단계 off → 비용 ~70% 절감), 각 줄 박스의 높이(px)만 잽니다.
2. **기준 높이 선택** — 검출된 높이 중 하위 `outlier_percentile`%(기본 5%)는 얼룩·노이즈로 버리고, 그다음으로 작은 줄의 높이를 기준으로 삼습니다.
3. **스케일 계산** — `scale = floor / 기준높이` (상한 1.0). 가장 작은 비-노이즈 줄이 `floor_char_height_px`(기본 18px)에 닿도록 하는 비율이며, 이미 그보다 크면 줄이지 않습니다.
4. **1회 리사이즈** — Lanczos로 한 번 줄여 무손실 WebP로 캐시합니다. 같은 이미지·설정의 다음 읽기는 캐시 적중(~100 ms).

검출되는 텍스트가 없으면(사진·아이콘·다이어그램) 원본을 그대로 돌려줍니다. 인식을 끄기 때문에 글자 종류(한글/한자 등)는 구분하지 못해서, 문자 체계에 맞는 `floor_char_height_px`는 설정에서 지정합니다.

## 설정

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `floor_char_height_px` | `18` | 출력 이미지에서 가장 작은 비노이즈 글자의 최소 line height(px). 권장: **12**(라틴 전용), **18**(한글/가나, 기본값), **24**(간체 CJK), **32**(번체 CJK). |
| `outlier_percentile` | `5` | 검출된 글자 높이 중 하위 N%는 노이즈로 폐기. |
| `min_pixels_for_action` | `200000` | 이보다 작은 이미지는 `shrink:` 가 붙어도 그대로 통과. |
| `enabled` | `true` | 전체 파이프라인 토글. off면 `shrink:`는 제거되지만 원본이 반환됩니다. |

`/plugin config glyphfit`으로 변경.

## 트레이드오프

- **컨텐츠의 문자 체계에 맞춰 `floor_char_height_px`를 설정하세요.** 한국어/일본어는 ~18, 한자는 ~24가 적절. 기본값은 한국어에 안전한 값입니다.
- **첫 실행 비용은 두 단계.** 첫 세션에서 `uv sync`가 의존성(Pillow, ONNX Runtime, RapidOCR — 수십 MB, 캐시가 없으면 더 느림)을 설치하고, 첫 `shrink:` 읽기에서 RapidOCR이 ~50 MB 검출 모델을 1회 받습니다. 둘 다 1회성이며 이후 캐시 적중은 ~100 ms입니다.
- **`shrink:`가 no-op일 수 있음.** 검출되는 텍스트가 없거나(사진/아이콘/다이어그램), 이미 작거나(~200k px 미만), 텍스트가 이미 floor 이상이면 원본이 그대로 반환됩니다.
- **캐시 적중은 거의 무료.** 같은 이미지 + 같은 설정이면 ~100 ms.
